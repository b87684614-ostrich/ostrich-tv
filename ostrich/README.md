# 🦤 Страус.TV

Видеоплатформа в стиле классического видеохостинга с оранжевыми акцентами и страусиным брендингом.
**Node.js + Express + SQLite**, фронтенд на чистом JavaScript (SPA).

Платформа стартует **с пустой базой**: нет демо-пользователей, демо-видео и заглушек. Всё создают сами посетители.

---

## Возможности

**Пользователи**
- Регистрация и вход только по логину и паролю (без e-mail и телефона), пароли хэшируются через bcrypt
- 12 стандартных страусиных аватарок или загрузка своего фото
- Загрузка видео: название, описание, обложка (своя или автоматически из кадра видео), индикатор прогресса
- Просмотр видео, лайки и дизлайки, комментарии, счётчик просмотров
- Каналы: свой и чужие, подписки, лента подписок, понравившиеся видео
- Поиск, «В тренде», тёмная и светлая тема, адаптивная вёрстка для телефона
- Жалобы на видео, комментарии и каналы

**Скрытая панель администратора** — сочетание **S + Tab** (на телефоне: адрес `/#/admin`)
- Обзор: пользователи, онлайн, видео, место на диске, жалобы
- Видео: полный список, скрыть/показать, удалить навсегда (файл стирается с сервера)
- Пользователи: карточка с мерами:
  - **войти под аккаунтом** (вход под чужим аккаунтом, сверху оранжевая полоса «Вернуться к себе»)
  - предупреждение (пользователь увидит его при следующем визите)
  - запрет комментариев на 1/3/7/30 дней или навсегда
  - запрет загрузки видео
  - сброс имени/аватара/описания (если они оскорбительные)
  - удаление всех комментариев пользователя, завершение всех его сеансов
  - роли: пользователь / модератор / администратор
  - галочка «подтверждённый канал», смена пароля
  - временная или постоянная блокировка с причиной, полное удаление аккаунта
- Комментарии: поиск и удаление
- Жалобы: очередь с быстрыми действиями
- Журнал действий всех админов и модераторов
- Настройки сайта: открыть/закрыть регистрацию, разрешить/запретить загрузку, объявление для всех, фильтр запрещённых слов

### Как стать администратором
1. Задайте на сервере переменную окружения `ADMIN_KEY` (длинный секретный ключ).
2. Зарегистрируйтесь на сайте обычным способом.
3. Нажмите **S + Tab** и введите ключ. Ваш аккаунт получит роль администратора.
4. Дальше можно назначать модераторов прямо в панели.

> Если `ADMIN_KEY` не задан, сервер при запуске сгенерирует временный ключ и напишет его в логи.

## Локальный запуск

```bash
npm install
ADMIN_KEY=мой-секретный-ключ npm start
# открыть http://localhost:3000
```
Windows (PowerShell): `$env:ADMIN_KEY="мой-ключ"; npm start`

Требуется Node.js 18–22 (рекомендуется 22 LTS).

### Переменные окружения
| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | Порт (Render задаёт сам) |
| `DATA_DIR` | `./data` | Папка для базы и загруженных файлов |
| `ADMIN_KEY` | случайный | Секретный ключ для получения прав администратора |
| `MAX_UPLOAD_MB` | `500` | Максимальный размер видео |
| `NODE_ENV` | — | `production` включает Secure-cookie и HSTS |

## 🚀 Публикация на Render без ошибок

### ⚠️ Сначала главное: где хранятся видео
На Render у сервисов **временная файловая система**: всё записанное на диск (SQLite-база и видео) **стирается** при каждом деплое, перезапуске, а на бесплатном тарифе ещё и при засыпании после 15 минут без посетителей.
Поэтому для настоящей работы нужен **платный тариф (Starter) с постоянным диском (Persistent Disk)**. Именно так настроен `render.yaml`.
На бесплатном тарифе сайт тоже запустится, но годится только для демонстрации: пользователи и видео будут пропадать.

### Шаг 1. Загрузите проект на GitHub
```bash
git init
git add .
git commit -m "Страус.TV"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ostrich-tv.git
git push -u origin main
```
Папки `node_modules` и `data` в репозиторий не попадают (они в `.gitignore`), так и должно быть.

### Шаг 2. Вариант А — через Blueprint (проще всего)
1. Зайдите на https://dashboard.render.com → **New → Blueprint**.
2. Выберите репозиторий. Render прочитает `render.yaml`.
3. Когда попросит значение `ADMIN_KEY`, введите длинный случайный ключ (например, 30+ символов).
4. Нажмите **Apply** и дождитесь статуса **Live**.

### Шаг 2. Вариант Б — вручную
1. **New → Web Service** → выберите репозиторий.
2. Настройки:
   - **Runtime:** Node
   - **Region:** Frankfurt
   - **Build Command:** `npm ci --omit=dev`
   - **Start Command:** `node server.js`
   - **Instance Type:** Starter (или выше)
3. **Environment Variables:**
   - `NODE_VERSION` = `22`
   - `NODE_ENV` = `production`
   - `DATA_DIR` = `/var/data`
   - `ADMIN_KEY` = ваш секретный ключ
4. **Advanced → Add Disk:** Mount Path = `/var/data`, Size = 10 GB (потом можно увеличить, уменьшить нельзя).
5. **Advanced → Health Check Path:** `/healthz`
6. **Create Web Service**.

### Шаг 3. Первый вход
Откройте адрес `https://ostrich-tv.onrender.com` (или ваш), зарегистрируйтесь, нажмите **S + Tab**, введите `ADMIN_KEY`.

### Частые ошибки и решения
| Проблема | Решение |
|---|---|
| `better-sqlite3` не собирается / `NODE_MODULE_VERSION` | Задайте `NODE_VERSION=22` (есть файл `.node-version`). Не используйте Node 23+ |
| `npm ci` ругается на lock-файл | Закоммитьте `package-lock.json` вместе с проектом |
| Пользователи и видео пропали | Не подключён диск или `DATA_DIR` не совпадает с Mount Path диска |
| Видео не загружается, ошибка 413 / обрыв | Файл больше `MAX_UPLOAD_MB`, или медленный интернет. Увеличьте лимит или сожмите видео |
| Видео загрузилось, но не играет | Браузер не поддерживает кодек (например, HEVC/.mkv). Загружайте MP4 (H.264) или WebM |
| Не могу войти после деплоя (cookie) | Открывайте сайт по `https://`. С `NODE_ENV=production` cookie работает только по HTTPS |
| Деплой с диском занимает больше времени | Это нормально: с диском Render останавливает старую версию перед запуском новой (короткий простой) |

## 🛡️ Как не попасть под антифишинговые фильтры

Браузеры (Google Safe Browsing, SmartScreen) помечают сайты как фишинговые, если те **копируют чужой бренд и форму входа**, чтобы выманить пароли. В проекте уже сделано:

- ✅ **Свой бренд**: название «Страус.TV», свой логотип. Нигде нет слов «YouTube», «Google», чужих логотипов и кнопки «Войти через Google».
- ✅ Сайт **не запрашивает e-mail, телефон и пароли от других сервисов**. Об этом прямо написано на формах входа и регистрации.
- ✅ Страницы **«Правила»** и **«Политика конфиденциальности»**, в подвале пометка «Независимый проект».
- ✅ HTTPS (Render выдаёт сертификат автоматически), HSTS, строгая политика безопасности (CSP), защитные заголовки.
- ✅ Пароли хэшируются bcrypt, cookie `HttpOnly` + `SameSite`, ограничение числа попыток входа.
- ✅ Правильные атрибуты `autocomplete`: менеджеры паролей распознают форму как обычную.

**Что сделать вам:**
1. Не называйте домен и сервис похоже на YouTube (никаких `youtube-…`, `yuotube`, `ytube-login`).
2. По возможности подключите **свой домен** (Render → Settings → Custom Domains). Адреса `*.onrender.com` иногда проверяют строже, потому что там бывают мошеннические сайты.
3. Добавьте сайт в **Google Search Console** — там же можно запросить проверку, если сайт вдруг пометят.
4. Не рассылайте ссылки на вход массово в мессенджерах и почте, особенно с текстом вида «подтвердите аккаунт».
5. Если сайт всё-таки пометили: https://safebrowsing.google.com/safebrowsing/report_error/ → «Сообщить об ошибке».
